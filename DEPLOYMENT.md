# Deployment Guide

Step-by-step instructions to deploy this service to Render's free tier.

**Stack:** Spring Boot app on Render (Docker) + Render PostgreSQL (free 90-day) + Upstash Redis (free forever)

**Total time:** ~15 minutes

---

## Prerequisites

- GitHub account with this repo pushed to it
- Render account at https://render.com (free)
- Upstash account at https://upstash.com (free)

---

## Step 1 — Create the Redis database on Upstash

1. Sign in to [Upstash Console](https://console.upstash.com/).
2. **Create Database** → choose a region close to your Render region (e.g. `us-east-1`).
3. After creation, copy the **Redis URL** — it looks like:
   ```
   rediss://default:xxxxxxxxxxxxxxxx@hostname.upstash.io:6379
   ```
4. Keep this URL; you'll paste it into Render in Step 3.

> **Why Upstash?** Render's managed Redis requires a paid plan. Upstash's free tier gives 10 000 commands/day and 256 MB — more than enough for a portfolio demo.

---

## Step 2 — Deploy to Render via Blueprint

1. Go to [Render Dashboard](https://dashboard.render.com/) → **New** → **Blueprint**.
2. Connect your GitHub account and select the `url-shortener` repository.
3. Render reads `render.yaml` and shows you the resources it will create:
   - Web service: `url-shortener` (Docker, free plan)
   - PostgreSQL: `url-shortener-db` (free 90-day trial)
4. Click **Apply** — Render provisions the database and queues the first build.

---

## Step 3 — Set the remaining environment variables

After the blueprint is applied, go to **url-shortener** → **Environment** and add:

| Key | Value | Notes |
|---|---|---|
| `REDIS_URL` | `rediss://default:xxx@hostname.upstash.io:6379` | From Upstash Step 1 |
| `APP_BASE_URL` | `https://url-shortener.onrender.com` | Your Render service URL |

`JWT_SECRET` is auto-generated by Render (the `generateValue: true` in `render.yaml`).

Database variables (`DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`) are wired automatically from the managed PostgreSQL — you don't need to set these.

---

## Step 4 — Trigger the first deploy

After setting the environment variables, go to **Deploys** → **Trigger deploy** (or push any commit to `main`).

Watch the build log. The Maven build takes ~3 minutes. You'll see Flyway migrations run and Spring Boot start.

**Expected final log lines:**
```
Flyway: Successfully applied 6 migrations
Started UrlShortenerApplication in 8.4 seconds
```

---

## Step 5 — Verify the deployment

Once the deploy shows **Live**, run the smoke tests:

```bash
bash bin/smoke-test.sh https://url-shortener.onrender.com
```

Or hit the endpoints manually:

```bash
# Health
curl https://url-shortener.onrender.com/actuator/health

# Shorten a URL
curl -X POST https://url-shortener.onrender.com/api/v1/urls \
  -H "Content-Type: application/json" \
  -d '{"longUrl": "https://github.com"}'

# Redirect (use the shortCode from the response above)
curl -i https://url-shortener.onrender.com/aB3x9
```

---

## Step 6 — Set up GitHub Actions CI/CD

The workflow in `.github/workflows/ci-cd.yml` runs tests on every push and deploys to Render on merges to `main`.

**GitHub secrets to add** (Settings → Secrets and variables → Actions → New repository secret):

| Secret name | How to get it |
|---|---|
| `RENDER_DEPLOY_HOOK_URL` | Render → url-shortener → Settings → **Deploy Hook** → copy the URL |
| `APP_BASE_URL` | Your `https://url-shortener.onrender.com` URL |

After adding the secrets, push a commit to `main` — the workflow will run tests, then trigger a Render deploy automatically.

## Step 8 — (Optional) Set up UptimeRobot

1. Go to [UptimeRobot](https://uptimerobot.com/) (free).
2. Add a new monitor: HTTP monitor → `https://url-shortener.onrender.com/actuator/health`.
3. Monitoring interval: 5 minutes.
4. Copy the **public status page URL** and add it as an uptime badge in README.

## Free tier limits and known gotchas

| Resource | Limit | Impact |
|---|---|---|
| Render web service | Spins down after 15 min inactivity | First request takes ~30-60 s to wake up |
| Render PostgreSQL | 90-day trial, then paused | Upgrade to a $7/mo paid plan before day 90 |
| Upstash Redis | 10 000 commands/day | ~8 000 redirects/day before cache gets expensive; disable caching if needed |
| Render RAM | 512 MB | JVM heap is capped at 75% (~384 MB) via `MaxRAMPercentage` |

**Cold start:** Render's free web services spin down after 15 minutes of inactivity. The first request after a sleep period takes 30-60 seconds (Render starts the container, JVM boots, Flyway validates). Add this note to your README so interviewers aren't confused.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `FlywayException: schema validation failed` | Entity fields don't match schema | Check latest migration vs JPA entities |
| `Connection refused` to Redis | `REDIS_URL` not set or wrong | Verify env var in Render → Environment |
| `HikariPool-1 - Connection is not available` | Too many connections | Reduce `maximum-pool-size` in `application-prod.yml` |
| `Cannot determine embedded database driver class` | Wrong DB URL format | Ensure `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` are all set |
| App starts but `/actuator/health` returns DOWN | Redis or DB unreachable | Check Render logs; verify secrets |
